# 人生第一次

> 每个人都会遇到第一次。这份手册把每一步写清楚，把坑标出来。

给第一次做某件事、身边又没人可问的普通成年人。每篇覆盖一个完整场景，按「准备 → 现场 → 出问题怎么办」的时间顺序写，篇首放一张 30 秒速查卡。

## 怎么读

**还有几天，提前准备。** 先看篇首「30 秒速查」，再看「准备事项」，照着清单勾。

**人已经在现场。** 直接看「现场流程」，找当前这一步；卡住了翻「特殊情况与应急」。

**已经做完，想弄明白。** 看「常见问题」和「避坑提醒」，再按「延伸资源」去官方页面核对。

**只想查一件事。** 打开 [index.html](index.html)，按关键词、栏目、耗时、花费、风险筛选。检索页需要本地起一个静态服务，见下面「本地运行」。

## 每篇长什么样

每篇固定 9 个板块，顺序不变：

1. 30 秒速查
2. 准备事项
3. 现场流程
4. 常见问题
5. 避坑提醒
6. 特殊情况与应急
7. 费用与时间预算
8. 延伸资源
9. 依据与核实

写作模板见 [meta/条目模板.md](meta/条目模板.md)，规范见 [meta/写作规范.md](meta/写作规范.md)。

## 事实怎么保证

- 每条关键事实标依据等级：Ⅰ 法规与强制标准、Ⅱ 官方办事指引、Ⅲ 多方一致的通行做法、Ⅳ 亲历者经验。
- 「必须」「不得」「否则会被拒绝」这类强制表述，只能由 Ⅰ 或 Ⅱ 级来源支撑。
- 每篇配一份 `sources/ID.核实.md`，记录文中说法、来源、原文摘录、访问日期。
- 查不到的内容写「待核实」，不写推测。
- 来源白名单、引用格式和链接失效处理，见 [meta/依据分级与引用规则.md](meta/依据分级与引用规则.md)。

## 本地运行

检索页是纯静态的，没有后端。因为浏览器不允许网页直接读本地 JSON，需要起一个静态服务：

```bash
cd HowToFirstTime   # 或你的本地目录名
node tools/serve.mjs
```

然后打开 `http://localhost:8000/`。也可以用 Python：

```bash
python -m http.server 8000
```

重新生成索引：

```bash
node tools/build-index.mjs
```

跑全部检查：

```bash
node tools/check-frontmatter.mjs
node tools/check-structure.mjs
node tools/check-refs.mjs
node tools/check-stale.mjs
node tools/check-todo.mjs
node tools/check-links.mjs
```
