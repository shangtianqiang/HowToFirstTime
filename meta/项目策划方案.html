一、项目定位

1.1 一句话定位

给第一次做某件事、身边又没人可问的普通成年人，一份按时间顺序写清楚「先做什么、在哪做、说什么、哪里容易错」的操作手册。

1.2 要解决的问题

第一次坐飞机的人，真正怕的不是「飞机危不危险」，而是：

  • 提前多久到？走错航站楼怎么办？
  • 充电宝能不能带？液体能不能过安检？
  • 值机、托运、安检、登机，先做哪个？
  • 误机了、行李丢了，找谁？

现有内容的问题：

现状 问题
搜索引擎结果 广告、旧攻略、互相抄，不知道哪句还有效
短视频攻略 只讲一两个亮点，缺完整流程，看完仍不敢出门
官方页面 准确但分散在十几个页面，全是术语，第一次看的人不知道从哪读起
熟人经验 依赖运气，且往往漏掉对方已经习以为常的关键步骤

本项目要做的，是把分散的官方规则、机构流程和真实经验，压缩成一篇能从头读到尾、也能在现场直接翻的手册。

1.3 读者画像

维度 描述
年龄 18–35 岁为主，覆盖 35 岁以上转阶段人群（当爸爸、照顾父母）
身份 学生、初入职场者、新市民、新手父母
经验 对目标事项零经验或只有旁观经验
阅读设备 手机为主，少量电脑
阅读时间 事前 10–30 分钟；现场碎片时间；事后补课
核心诉求 不出错、不被坑、不花冤枉钱、出事知道找谁

1.4 三种使用场景（决定内容形态）

场景 读者状态 需要的内容 对应板块
事前突击 还有几天/几小时，来得及准备 结论、清单、要带什么 0. 速查卡 + 1. 准备事项
现场救急 人已经在机场/车站/医院 下一步做什么、找谁 2. 操作步骤 + 5. 特殊情况
事后补课 已经做完，想弄明白 为什么、下次怎么更好 3. FAQ + 4. 避坑 + 7. 延伸

因此每篇必须把「30 秒速查卡」放在最前面，详细解释放在后面。读者不按顺序读也能用。

1.5 内容边界

写：

  • 办事流程、规则、材料、时间节点、费用区间
  • 高频错误、骗局、合同陷阱、违规后果
  • 官方入口、投诉渠道、求助电话
  • 真实经验中「官方文件不会写、但第一次做的人一定会遇到」的细节

不写：

  • 景点推荐、产品比价、带货、课程推销
  • 医疗诊断、法律结论、投资建议
  • 需要专业资质的操作细节（手术、飞行操纵、危险作业）
  • 未经证实的偏方、捷径、「内部渠道」
  • 替读者做人生选择（要不要出国、要不要生孩子），只给事实、流程和后果

1.6 与参考项目的异同

参考项目的实际做法（据其 README 与 CLAUDE.md）：34 节、767 条建议；每条含「成本 / 说人话 / 收益 / 证据等级 / 来源 / 备注」；证据分 A/B/C；只引原始文献；纯静态检索页；每周链接巡检；可导出 PDF/EPUB/离线 HTML/Anki。

维度 参考项目 本项目 处理方式
组织单位 一条建议 = 一个可执行动作 一篇 = 一个完整「第一次」 保留「栏目 → 条目 → 编号」骨架，条目变长
核心问题 值不值得做（成本/收益） 怎么做、别做错（流程/风险） 用「时间轴 + 检查点」替代「成本/收益」
证据体系 期刊论文/官方文件，A/B/C 法规/官方指引/通行做法/个人经验，Ⅰ–Ⅳ 重新设计，不能照搬医学证据分级
表达核心 「说人话」一行 「30 秒速查卡」+ 分步说明 保留「说人话」精神，前移到篇首
检索维度 关键词/章节/证据/成本/人群 关键词/主题域/人生阶段/耗时/花费/风险/时效 扩展维度
维护机制 每周链接检查、统计同步 增加「时效复审」检查 新增 check-stale
输出形态 PDF/EPUB/离线/Anki 首期只做离线单文件 HTML + 可打印清单 降低初期维护成本

结论：复用「栏目 + 编号 + 来源可核 + 静态检索 + 定期巡检」的组织形式；不复用「性价比算账」和「A/B/C 证据分级」这两套不适配的机制。

取值约束：

  • volatility = S：多年稳定（如身份证办理基本流程），24 个月复审一次。
  • volatility = M：每年可能调整（如票价规则、社保基数），12 个月复审一次。
  • volatility = H：政策或规则随时变（签证、入境、安检），6 个月复审一次，且文首加「出行前再查一次官网」提示。
  • risk = 高 的条目，正文必须有「做错的后果」和「出问题找谁」两段。

步骤写法硬要求：

  1. 一步只做一件事，标题用动词开头（「托运行李」「过安检」）。
  2. 每步开头写位置：「在航站楼出发层，找航空公司值机柜台」。
  3. 写清楚看什么：「看头顶指示牌，跟着『安全检查』箭头走」。
  4. 写清楚说什么：「把身份证递给工作人员，说『值机』」。
  5. 写完成标志：「拿到登机牌和行李票，就算办完」。
  6. 写卡住时怎么办：「自助机打不出登机牌，去人工柜台」。

七、写作规范

7.1 语言规范

项 规则
人称 统一用「你」；涉及机构写清主体（航空公司、车站工作人员、医院）
句长 一句一件事；平均 ≤30 字，最长 ≤50 字
段落 每段 ≤5 句；一段只讲一个环节
语体 口语化书面语；不写公文腔，不写网络梗，不写营销腔
术语 首次出现用一句日常话解释，保留原词；同一板块不重复解释
标题 条目标题用「第一次X」或「第一次X：一句最关键提醒」；步骤标题用动词短语；FAQ 才用问句
数字 阿拉伯数字；金额写「元」；时间写「分钟/小时/天」；日期写「2026年10月23日」
单位 公里、米、公斤、升，不用「斤」「里」等口语单位（引用原文除外）
括号 括号内补充 ≤10 字；超过 10 字拆成独立句；不套括号
标点 少用破折号；不用分号并列长句；列举超过 3 项用列表

禁止的写法：

  • 元叙述：「本条讲的是」「这篇不劝你」「这一节算的是」。
  • 段尾升华：「从这一刻起，你就真正长大了」。
  • 空转加强词：「值得注意的是」「本质上」「不得不说」。
  • 需要读者二次翻译的比喻：「另一头」「那张皮」「挡箭牌」。
  • 电报体：把一句话拆成五六个两三字的短句。
  • 绝对化：「一定」「绝对」「百分之百」「包过」「永远不会」。
  • 恐吓式表达：「不这么做就完了」「后果不堪设想」。

7.2 事实与依据分级（Ⅰ–Ⅳ）

参考项目的 A/B/C 是医学证据分级，不适用于流程类内容。本项目改用依据来源分级：

等级 名称 定义 正文写法
Ⅰ 法规与强制标准 法律、行政法规、部门规章、国家标准，有文号，有官方原文 「按规定必须……」，可直接写强制
Ⅱ 官方办事指引 政府部门、公共服务机构、企业官方规则（12306、航司运输总条件、医院、银行、学校官网） 「按官方指引……」，可写流程和时限
Ⅲ 多方一致的通行做法 ≥2 个独立可信来源相互印证，或行业公认惯例 「通常」「多数情况下」，不得写成强制
Ⅳ 亲历者经验 署名、时间、地点、条件明确的个人经历 「有人遇到过……」「个人经验，不保证普遍适用」

使用规则：

  1. 「必须」「不得」「否则会被罚款/拒绝」这类强制表述，只能由 Ⅰ 或 Ⅱ 支撑。
  2. Ⅲ 级内容只能写成「通常做法」，并注明「以现场为准」。
  3. Ⅳ 级内容不能单独支撑任何流程步骤，只能作为提醒。
  4. 同一段里混用不同等级时，逐句标注或在本段末统一说明。
  5. 查不到依据的内容，写「待核实」并登记，不得用推测补齐。

7.4 时效与地域规范

  • 每篇必须写 last_verified，正文「依据与核实」同步显示。

  • 不做诊断、不判断病情、不推荐具体药物剂量。

  • PR 模板带发布前复核清单，10 项逐项勾选。

  • updates/YYYY-MM.md 按月记录：新增、修订、失效链接修复、复审通过。
  • 每篇正文顶部不写版本号，版本信息放在核实记录里，避免正文频繁变动。
  • README 显示「收录 N 篇 · 已核实 N 篇 · 最近更新 YYYY-MM-DD」，由脚本生成，不手写。
