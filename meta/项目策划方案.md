## 一、项目定位

### 1.1 一句话定位

**给第一次做某件事、身边又没人可问的普通成年人，一份按时间顺序写清楚「先做什么、在哪做、说什么、哪里容易错」的操作手册。**

### 1.2 要解决的问题

第一次坐飞机的人，真正怕的不是「飞机危不危险」，而是：

- 提前多久到？走错航站楼怎么办？
- 充电宝能不能带？液体能不能过安检？
- 值机、托运、安检、登机，先做哪个？
- 误机了、行李丢了，找谁？

现有内容的问题：

| 现状 | 问题 |
| --- | --- |
| 搜索引擎结果 | 广告、旧攻略、互相抄，不知道哪句还有效 |
| 短视频攻略 | 只讲一两个亮点，缺完整流程，看完仍不敢出门 |
| 官方页面 | 准确但分散在十几个页面，全是术语，第一次看的人不知道从哪读起 |
| 熟人经验 | 依赖运气，且往往漏掉对方已经习以为常的关键步骤 |

本项目要做的，是**把分散的官方规则、机构流程和真实经验，压缩成一篇能从头读到尾、也能在现场直接翻的手册**。

### 1.3 读者画像

| 维度 | 描述 |
| --- | --- |
| 年龄 | 18–35 岁为主，覆盖 35 岁以上转阶段人群（当爸爸、照顾父母） |
| 身份 | 学生、初入职场者、新市民、新手父母 |
| 经验 | 对目标事项**零经验或只有旁观经验** |
| 阅读设备 | 手机为主，少量电脑 |
| 阅读时间 | 事前 10–30 分钟；现场碎片时间；事后补课 |
| 核心诉求 | 不出错、不被坑、不花冤枉钱、出事知道找谁 |

### 1.4 三种使用场景（决定内容形态）

| 场景 | 读者状态 | 需要的内容 | 对应板块 |
| --- | --- | --- | --- |
| 事前突击 | 还有几天/几小时，来得及准备 | 结论、清单、要带什么 | 0. 速查卡 + 1. 准备事项 |
| 现场救急 | 人已经在机场/车站/医院 | 下一步做什么、找谁 | 2. 操作步骤 + 5. 特殊情况 |
| 事后补课 | 已经做完，想弄明白 | 为什么、下次怎么更好 | 3. FAQ + 4. 避坑 + 7. 延伸 |

**因此每篇必须把「30 秒速查卡」放在最前面**，详细解释放在后面。读者不按顺序读也能用。

### 1.5 内容边界

**写：**

- 办事流程、规则、材料、时间节点、费用区间
- 高频错误、骗局、合同陷阱、违规后果
- 官方入口、投诉渠道、求助电话
- 真实经验中「官方文件不会写、但第一次做的人一定会遇到」的细节

**不写：**

- 景点推荐、产品比价、带货、课程推销
- 医疗诊断、法律结论、投资建议
- 需要专业资质的操作细节（手术、飞行操纵、危险作业）
- 未经证实的偏方、捷径、「内部渠道」
- 替读者做人生选择（要不要出国、要不要生孩子），只给事实、流程和后果

### 1.6 与参考项目的异同

参考项目的实际做法（据其 README 与 CLAUDE.md）：34 节、767 条建议；每条含「成本 / 说人话 / 收益 / 证据等级 / 来源 / 备注」；证据分 A/B/C；只引原始文献；纯静态检索页；每周链接巡检；可导出 PDF/EPUB/离线 HTML/Anki。

| 维度 | 参考项目 | 本项目 | 处理方式 |
| --- | --- | --- | --- |
| 组织单位 | 一条建议 = 一个可执行动作 | 一篇 = 一个完整「第一次」 | 保留「栏目 → 条目 → 编号」骨架，条目变长 |
| 核心问题 | 值不值得做（成本/收益） | 怎么做、别做错（流程/风险） | 用「时间轴 + 检查点」替代「成本/收益」 |
| 证据体系 | 期刊论文/官方文件，A/B/C | 法规/官方指引/通行做法/个人经验，Ⅰ–Ⅳ | **重新设计**，不能照搬医学证据分级 |
| 表达核心 | 「说人话」一行 | 「30 秒速查卡」+ 分步说明 | 保留「说人话」精神，前移到篇首 |
| 检索维度 | 关键词/章节/证据/成本/人群 | 关键词/主题域/人生阶段/耗时/花费/风险/时效 | 扩展维度 |
| 维护机制 | 每周链接检查、统计同步 | 增加「时效复审」检查 | 新增 check-stale |
| 输出形态 | PDF/EPUB/离线/Anki | 首期只做离线单文件 HTML + 可打印清单 | 降低初期维护成本 |

**结论：复用「栏目 + 编号 + 来源可核 + 静态检索 + 定期巡检」的组织形式；不复用「性价比算账」和「A/B/C 证据分级」这两套不适配的机制。**

## 二、参考项目拆解（作为结构依据）

### 2.1 仓库结构

```
HowToLiveBetter/
├── README.md          # 门户：定位、问题导航表、阅读说明、条目格式示例、下载入口
├── book/              # 正文：34 个章节文件，NN-标题.md
├── docs/              # 长文 + 核实记录/
├── index.html         # 纯静态检索页，直接读 book/ 与 README
├── selfcheck.html     # 自查问答页
├── skills/            # AI 助手 skill，回答时注明节号条号
├── tools/             # 统计同步、引用检查、链接检查、EPUB/PDF/离线/Anki 构建
├── .github/workflows/ # 构建 + 每周链接巡检
├── updates.json       # 更新记录
└── LICENSE            # CC BY 4.0
```

### 2.2 内容组织

- 章：`book/21-出国旅行与境外安全.md`，开头 `[← 回总目录](../README.md)`，`# 21. 标题`，接 2–3 句栏目导语。
- 条：`### 1. 动词开头的建议标题`，下接固定字段：

```
<!-- 成本标签: 钱=0 时间=少 毅力=否 收益=大 口径=死亡率 -->
- 成本：
- 说人话：
- 收益：
- 证据等级：A / B / C
- 来源：
- 备注：
```

- 编号稳定：新条目一律追加到节末，不重排。
- 交叉引用必须带锚点词，禁止裸条号和「见下一条」。

### 2.3 质量机制

- 只引原始文献；禁止知乎、公众号、搜狐、网易、百家号等二手转述。
- 数字必须能在原文找到；找不到写「待核实」，不编 DOI。
- 「说人话」只翻方向和量级，不新增数字和事实。
- 句子控制在 30 字上下，最长 50 字；一句一件事。
- CI 每周检查失效链接；引用对照表随每次改动生成并人工看 diff。
- 统计数字由脚本同步，避免多处写死。

### 2.4 可直接复用 / 需改造 / 不可照搬

| 类别 | 内容 |
| --- | --- |
| 直接复用 | 栏目 + 稳定编号、篇首导语、来源可核、静态检索、离线单文件、CI 巡检、Issue 纠错模板 |
| 需改造 | 条目字段（成本/收益 → 准备/步骤/FAQ/避坑）、证据分级（A/B/C → Ⅰ–Ⅳ）、筛选维度 |
| 不可照搬 | 「性价比」排序与筛选、医学证据等级、Anki 牌组（首期不需要） |

- 条目内部步骤增删后，若步骤号变化，必须同步全库交叉引用。

**划分原则：**

1. 按「读者要办的事」分，不按学科分。

4. 每个栏目一个 `00-栏目导读.md`，3–5 句说清这个域最容易踩的坑和推荐阅读顺序。

条目超过 8 篇的栏目，在 `00-栏目导读.md` 里给分组导航，例如「出行与交通」分为：

- 城际出行：飞机、高铁、普速火车、长途大巴
- 市内出行：地铁、公交、网约车、电动车
- 自驾相关：租车、自驾长途
- 特殊场景：春运、独自旅行、带老人小孩出行

## 五、内容组织方式

### 5.1 三层结构

```
栏目（主题域）
  └── 条目（一个完整的「第一次」）
        └── 板块（固定 9 块，顺序不变）
              └── 步骤（编号，按现场先后）
```

**一篇 = 一个场景 = 一次能读完并照着做完的闭环。** 不把「坐飞机」拆成「买票」「安检」「登机」三篇，否则读者要在多个页面之间跳。

### 5.2 条目标准骨架

每篇严格按以下顺序，板块名称不改：

```markdown
---
id: A-01
title: 第一次坐飞机
domain: 出行与交通
stage: [学生, 初入职场]
prerequisites: [有效身份证件]
duration: 半天
cost: 千元级
risk: 中
volatility: M
region: 中国大陆
last_verified: 2026-10-23
status: 已核实
source_count: 12
related: [B-01, A-02]
---
```

### 5.3 元数据字段（front-matter）

| 字段 | 取值 | 用途 |
| --- | --- | --- |
| `id` | `A-01` | 唯一标识、交叉引用、核实记录对应 |
| `title` | `第一次坐飞机` | 检索与目录 |
| `domain` | 十个栏目之一 | 栏目筛选 |
| `stage` | 人生阶段数组，如 `[学生, 初入职场, 新手父母]` | 阶段筛选 |
| `prerequisites` | 前置条件数组，如 `[身份证, 银行卡]` | 提示读者先看什么 |
| `duration` | `半小时内` / `半天` / `1-3天` / `长期` | 耗时筛选 |
| `cost` | `免费` / `百元内` / `千元级` / `万元级` | 花费筛选 |
| `risk` | `低` / `中` / `高` | 风险筛选（高 = 做错会有法律、健康或较大财产后果） |
| `volatility` | `S` / `M` / `H` | 时效复审周期 |
| `region` | `全国` / `分省` / `分市` / `分机构` | 地域差异提示 |
| `last_verified` | `YYYY-MM-DD` | 最近核实日期 |
| `status` | `初稿` / `已核实` / `待更新` / `有争议` | 可信度提示 |
| `source_count` | 数字 | 来源数量，低于阈值在检索页标黄 |
| `related` | ID 数组 | 相关条目 |

**取值约束：**

- `volatility = S`：多年稳定（如身份证办理基本流程），24 个月复审一次。
- `volatility = M`：每年可能调整（如票价规则、社保基数），12 个月复审一次。
- `volatility = H`：政策或规则随时变（签证、入境、安检），6 个月复审一次，且文首加「出行前再查一次官网」提示。
- `risk = 高` 的条目，正文必须有「做错的后果」和「出问题找谁」两段。

### 5.4 各板块写作要求

| 板块 | 回答什么问题 | 必写 | 不写 | 篇幅 |
| --- | --- | --- | --- | --- |
| 0. 30 秒速查 | 我现在最需要知道什么 | 4–6 条结论，每条一行 | 解释、背景 | ≤150 字 |
| 1. 准备事项 | 提前要做什么、带什么 | 按「提前 7 天 / 24 小时 / 出门前」分组；材料清单可勾选 | 现场步骤 | 600–1200 字 |
| 2. 操作步骤 | 到了现场按什么顺序做 | 每步写「在哪、看什么、说什么、完成标志」 | 原理、历史 | 1500–3000 字 |
| 3. 常见问题 | 大家最常问什么 | ≥10 条真实问题，一问一答 | 与正文重复的内容 | 每条 ≤120 字 |
| 4. 避坑提醒 | 哪些地方会多花钱、被骗、违规 | ≥8 条，每条写「坑是什么 + 怎么躲」 | 泛泛而谈的「注意安全」 | 每条 ≤150 字 |
| 5. 特殊情况 | 出错了怎么办 | 误机/丢失/生病/被拒/取消等 ≥5 种 | 正常流程 | 600–1200 字 |
| 6. 费用与时间 | 要花多少钱、多少时间 | 表格；给区间和可选/必选 | 具体商家比价 | 1 张表 |
| 7. 延伸资源 | 还想深入看什么 | 官方入口、相关条目、可打印清单 | 广告、课程推销 | 5–10 条 |
| 8. 依据与核实 | 这些话凭什么 | 依据等级、来源数、核实日期、适用范围、易变项 | 大段原文 | ≤200 字 |

**步骤写法硬要求：**

1. 一步只做一件事，标题用动词开头（「托运行李」「过安检」）。
2. 每步开头写位置：「在航站楼出发层，找航空公司值机柜台」。
3. 写清楚看什么：「看头顶指示牌，跟着『安全检查』箭头走」。
4. 写清楚说什么：「把身份证递给工作人员，说『值机』」。
5. 写完成标志：「拿到登机牌和行李票，就算办完」。
6. 写卡住时怎么办：「自助机打不出登机牌，去人工柜台」。

### 5.5 交叉引用规则

格式统一为：

```
见 A-02《第一次坐高铁》2.3「过安检」
```

规则：

- 必须带**条目标题 + 步骤号 + 步骤名**，三者缺一不可。
- 禁止裸编号（「见 A-02」）和相对指路（「见下一篇」「见上文」）。
- 相关条目在 front-matter 和文末「延伸资源」各出现一次，两处保持一致。
- 步骤号变动时，`check-refs.mjs` 负责找出失效引用。

### 5.6 检索与导航设计

**README 门户：**

1. 一句话定位 + 三个场景入口：「我要出门」「我要办事」「我要开始学」。
2. 「问题 → 条目」导航表，例如「第一次坐飞机要注意什么 → A-01」。
3. 全量目录（按栏目分组，显示条目状态和最近核实日期）。
4. 四条阅读路径：按人生阶段、按场景、按耗时、按风险。
5. 贡献指南与免责声明入口。

**静态检索页 `index.html`：**

- 数据来自 `index.json`，由 `build-index.mjs` 从 front-matter 和标题生成。
- 筛选维度：

| 维度 | 选项 |
| --- | --- |
| 关键词 | 全文标题、速查卡、FAQ |
| 主题域 | A–J |
| 人生阶段 | 学生 / 初入职场 / 新婚 / 新手父母 / 中年 / 退休 |
| 预计耗时 | 半小时内 / 半天 / 1–3 天 / 长期 |
| 花费 | 免费 / 百元内 / 千元级 / 万元级 |
| 风险 | 低 / 中 / 高 |
| 时效 | S / M / H（H 级标红） |
| 状态 | 已核实 / 待更新 / 初稿 |

- 提供「现场模式」：只显示速查卡，隐藏长文，适合手机竖屏。
- 提供「只看已核实」开关，默认开启。
- 每张卡片显示：标题、一句话、耗时、花费、风险、最近核实日期、状态。

**可打印清单 `checklists/`：**

- 每篇一张 A4 一页，只保留「要带什么、要做什么、出问题找谁」。
- 用 Markdown 复选框，打印后可手写勾选。

## 六、核心信息维度（必须覆盖）

每个「第一次」条目，必须回答下表 12 个维度的问题。缺少任一维度，视为未完成。

| # | 维度 | 必须回答 | 判断标准 |
| --- | --- | --- | --- |
| 1 | 适用边界 | 谁适用、谁不适用、和哪个相邻条目容易混 | 读者能判断「这篇是不是写给我看的」 |
| 2 | 前置条件 | 需要什么证件、资格、账号、预约 | 缺一样就办不成的事全部列出 |
| 3 | 时间轴 | 提前多久准备、每个环节耗时、截止时间 | 读者能倒推出「今天该做什么」 |
| 4 | 准备事项 | 材料、物品、钱、App、预约 | 可勾选，能打印 |
| 5 | 操作步骤 | 在哪、做什么、看什么、说什么、完成标志 | 没做过的人能照着走 |
| 6 | 费用构成 | 必选/可选、区间、退改规则 | 读者知道大概要花多少、哪些能省 |
| 7 | 常见问题 | ≥10 条真实高频问题 | 问题来自搜索、问答、访谈，不是作者想象 |
| 8 | 避坑提醒 | ≥8 条骗局、加价、合同陷阱、违规 | 每条都有具体场景和躲法 |
| 9 | 特殊情况 | 误机、丢失、生病、被拒、取消、纠纷 | 出问题知道第一步找谁 |
| 10 | 地区与机构差异 | 全国统一还是分省分市、哪些以现场为准 | 不会把一地经验当成全国规则 |
| 11 | 时效提示 | 哪些规则易变、截至什么时候、去哪查最新 | 读者知道这条可能过期 |
| 12 | 依据与出处 | 每条关键事实的来源、等级、原文位置 | 可逐条核对，不靠作者权威 |

**「真实经验」的使用边界：**

- 只写进「避坑提醒」「常见问题」「现场细节」，不写进强制流程。
- 必须署昵称、时间、地点、适用条件。
- 标注「个人经验，不保证普遍适用」。
- 不得作为某条规则的唯一依据；与官方说法冲突时，以官方为准，并在备注说明差异。

## 七、写作规范

### 7.1 语言规范

| 项 | 规则 |
| --- | --- |
| 人称 | 统一用「你」；涉及机构写清主体（航空公司、车站工作人员、医院） |
| 句长 | 一句一件事；平均 ≤30 字，最长 ≤50 字 |
| 段落 | 每段 ≤5 句；一段只讲一个环节 |
| 语体 | 口语化书面语；不写公文腔，不写网络梗，不写营销腔 |
| 术语 | 首次出现用一句日常话解释，保留原词；同一板块不重复解释 |
| 标题 | 条目标题用「第一次X」或「第一次X：一句最关键提醒」；步骤标题用动词短语；FAQ 才用问句 |
| 数字 | 阿拉伯数字；金额写「元」；时间写「分钟/小时/天」；日期写「2026年10月23日」 |
| 单位 | 公里、米、公斤、升，不用「斤」「里」等口语单位（引用原文除外） |
| 括号 | 括号内补充 ≤10 字；超过 10 字拆成独立句；不套括号 |
| 标点 | 少用破折号；不用分号并列长句；列举超过 3 项用列表 |

**禁止的写法：**

- 元叙述：「本条讲的是」「这篇不劝你」「这一节算的是」。
- 段尾升华：「从这一刻起，你就真正长大了」。
- 空转加强词：「值得注意的是」「本质上」「不得不说」。
- 需要读者二次翻译的比喻：「另一头」「那张皮」「挡箭牌」。
- 电报体：把一句话拆成五六个两三字的短句。
- 绝对化：「一定」「绝对」「百分之百」「包过」「永远不会」。
- 恐吓式表达：「不这么做就完了」「后果不堪设想」。

### 7.2 事实与依据分级（Ⅰ–Ⅳ）

参考项目的 A/B/C 是医学证据分级，不适用于流程类内容。本项目改用**依据来源分级**：

| 等级 | 名称 | 定义 | 正文写法 |
| --- | --- | --- | --- |
| Ⅰ | 法规与强制标准 | 法律、行政法规、部门规章、国家标准，有文号，有官方原文 | 「按规定必须……」，可直接写强制 |
| Ⅱ | 官方办事指引 | 政府部门、公共服务机构、企业官方规则（12306、航司运输总条件、医院、银行、学校官网） | 「按官方指引……」，可写流程和时限 |
| Ⅲ | 多方一致的通行做法 | ≥2 个独立可信来源相互印证，或行业公认惯例 | 「通常」「多数情况下」，不得写成强制 |
| Ⅳ | 亲历者经验 | 署名、时间、地点、条件明确的个人经历 | 「有人遇到过……」「个人经验，不保证普遍适用」 |

**使用规则：**

1. 「必须」「不得」「否则会被罚款/拒绝」这类强制表述，只能由 Ⅰ 或 Ⅱ 支撑。
2. Ⅲ 级内容只能写成「通常做法」，并注明「以现场为准」。
3. Ⅳ 级内容不能单独支撑任何流程步骤，只能作为提醒。
4. 同一段里混用不同等级时，逐句标注或在本段末统一说明。
5. 查不到依据的内容，写「待核实」并登记，不得用推测补齐。

### 7.3 来源规范

**只收：**

- 法律法规数据库、国务院及各部委官网（gov.cn）
- 机构官网：国家移民管理局、外交部领事服务网、12306、民航局、交管12123、各地政务服务平台、医院/银行/学校官网
- 企业官方规则：航空公司运输总条件、铁路旅客运输规程、平台服务协议
- 国际组织：WHO、UNICEF、CEFR 等官方文件
- 一手媒体：署名记者的原创调查或现场报道（仅用于证明「发生过」，不作为规则依据，需附网页存档）

**不收：**

- 知乎、微信公众号、小红书、抖音、百度百科、百家号、搜狐号、网易号
- 聚合站、攻略站、内容农场、AI 生成内容
- 中介广告、驾校销售话术、留学中介宣传页
- 无法追溯作者的「网友说」

**引用格式：**

```
[1] 中国民用航空局. 公共航空运输旅客服务管理规定（交通运输部令2021年第3号）. https://www.caac.gov.cn/... 访问日期：2026-10-23.
```

正文用 `[1]` 上标标注关键事实；文末「依据与核实」列全部来源；`sources/ID.核实.md` 存原文关键句摘录。

**链接失效处理顺序：**

1. 换同一机构官网的新地址。
2. 换能逐字核对同一事实的另一份官方原文。
3. 使用 web.archive.org 存档，注明「原页面已下线，此为某年某月某日存档」。

### 7.4 时效与地域规范

- 每篇必须写 `last_verified`，正文「依据与核实」同步显示。
- `volatility = H` 的条目，在标题下加一行：「以下规则截至 2026年10月，出发前请再查一次官网。」
- 涉及地方政策的（生育津贴、医保报销、居住证、公积金），必须写「以当地为准」，并给出查询入口，不写死某一城市的标准。
- 政策已变更但未复核的条目，状态改为「待更新」，检索页标黄。
- 法规修订、重大事故、平台规则变更后，相关条目立即复审，不等周期。

### 7.5 医疗、法律、金融边界

- 不做诊断、不判断病情、不推荐具体药物剂量。
- 不预测诉讼结果、不替代律师意见。
- 不推荐具体理财产品、不承诺收益。
- 统一写法：「这一步该问谁」「要带什么材料」「大概流程是什么」，而不是「你应该怎么做决定」。
- `DISCLAIMER.md` 写明：本手册只提供流程与公开信息，不构成医疗、法律、投资建议；紧急情况先联系专业人员。

### 7.6 格式规范

- 一篇正文控制在 4000–8000 字；超过 10000 字拆成「主篇 + 专题长文」。
- 步骤编号连续，不跳号；新增步骤插在末尾或整段重排并同步引用。
- 表格不超过 6 列；手机上能横向滚动。
- 图片只用于「指示牌、票据、界面截图」这类必须看的画面；每张图配一句说明；不使用装饰图。
- 外链统一放在「延伸资源」和「依据与核实」，正文中间不放推广链接。

## 八、调研与核实流程

### 8.1 单篇生产流水线（七步）

| 步骤 | 动作 | 产出 | 完成标志 |

### 8.2 问题清单法（六维）

| 维度 | 要问的问题 | 示例（坐飞机） |
| --- | --- | --- |
| 人 | 谁要做？年龄、证件、资格限制？ | 未成年人能单独坐吗？ |
| 事 | 先后顺序？每步完成标志？ | 先值机还是先托运？ |
| 时 | 提前多久？各环节耗时？截止时间？ | 起飞前多久停止值机？ |
| 地 | 去哪？哪个窗口、网站、App？ | T2 还是 T3？ |
| 钱 | 花多少？哪些必选？怎么退？ | 行李超重怎么收费？ |
| 险 | 最容易错在哪？被骗/被罚/被拒？找谁？ | 误机了还能改签吗？ |

问题来源优先级：官方 FAQ > 搜索引擎「大家还在问」> 问答社区高赞问题 > 对 3–5 位零经验者的访谈。**不凭作者想象编问题。**

2. **高损失**：做错会导致被拒、被罚、被骗、健康受损或损失上千元。
3. **高时效**：规则每年变，旧攻略容易误导。
4. **高搜索量**：搜索引擎和问答平台长期有人问。

只满足一条的进 P1；需要专业资质或受众很窄的进 P2。

## 十、质量与维护机制

### 10.1 自动检查（CI）

| 检查 | 脚本 | 失败条件 |
| --- | --- | --- |
| 元数据 | `check-frontmatter.mjs` | 缺字段、取值不在枚举内、ID 重复 |
| 链接 | `check-links.mjs` | 返回 404/410；每周一跑 |
| 时效 | `check-stale.mjs` | 超过 S/M/H 对应复审周期 |
| 交叉引用 | `check-refs.mjs` | 引用不带标题锚点、指向不存在的步骤 |
| 结构 | `check-structure.mjs` | 缺板块、板块顺序错误、步骤编号跳号 |
| 待核实 | `check-todo.mjs` | 「待核实」超过 30 天未处理 |

CI 只报警不自动改；`status = 待更新` 的条目在检索页标黄，不阻断发布。

### 10.2 Issue 与 PR

- **纠错**：必须填「条目 ID + 正文原句 + 正确说法 + 来源链接 + 访问日期」。
- **新条目**：必须填「为什么是第一次 + 目标读者 + 3 个核心问题 + 2 个官方来源」。
- **内容过时**：必须填「哪条规则变了 + 官方新链接 + 生效日期」。
- PR 模板带发布前复核清单，10 项逐项勾选。

### 10.3 更新与版本

- `updates/YYYY-MM.md` 按月记录：新增、修订、失效链接修复、复审通过。
- 每篇正文顶部不写版本号，版本信息放在核实记录里，避免正文频繁变动。
- README 显示「收录 N 篇 · 已核实 N 篇 · 最近更新 YYYY-MM-DD」，由脚本生成，不手写。

### 10.4 免责声明

`DISCLAIMER.md` 与 README 底部各放一份，写明：

- 内容为公开信息整理，不构成医疗、法律、投资建议。
- 政策与机构规则会变，办事前以官方最新公告为准。
- 个人经验部分不保证普遍适用。
- 紧急情况先联系专业人员或拨打急救电话。
- 欢迎纠错，但不接受删改来源的「经验之谈」。

## 十二、风险与对策

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| 政策过时 | 签证、医保、社保规则变了，正文还是旧的 | 时效分级 + 复审周期 + 文首日期 + CI 超期报警 |
| 地区差异 | 把某市经验写成全国规则 | `region` 字段 + 「以当地为准」+ 官方查询入口 |
| 机构规则变动 | 航司、平台、医院流程调整 | 以官方页面为准 + 来源标注访问日期 |
| 个人经验偏差 | 一个人的顺利经历被当成通用流程 | Ⅳ 级只进提醒，不进强制步骤；署名 + 条件 |
| 专业边界 | 医疗、法律、投资内容越界 | 只写流程和「问谁」，不写结论；免责声明 |
| 维护成本 | 篇数越多，过期越快 | 先做 8 篇跑通模板；脚本自动化；P0 优先 |
| 内容被误读 | 读者把旧版本当最新 | 每篇显示核实日期；检索页标状态；更新日志 |
| 商业化压力 | 广告、带货、卖课混入 | 项目规则明确禁止；来源白名单约束 |

## 十三、验收标准（整体）

1. **结构完整**：10 个栏目、94 个条目 ID、首批 8 篇落位，无重复 ID。
2. **模板统一**：8 篇均含 9 个板块，板块顺序一致，front-matter 字段齐全。
3. **事实可核**：每篇 ≥10 个来源，≥60% 为 Ⅰ/Ⅱ 级；核实记录能逐条定位原文。
4. **强制表述有据**：所有「必须/不得/否则」都能追到 Ⅰ/Ⅱ 级来源。
5. **读者可用**：找 3 名零经验者，只给速查卡，能独立完成一次流程或明确知道该问谁。
6. **检索可用**：按关键词、栏目、阶段、耗时、花费、风险、时效、状态八个维度能筛出目标条目。
7. **维护可跑**：CI 五项检查通过；`check-stale` 能正确列出超期条目。
8. **边界清晰**：无医疗诊断、法律结论、投资建议、绝对化承诺；免责声明到位。
